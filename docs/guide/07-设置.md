# 07 · 设置

> 适用版本：v1.8.4
>
> 设置改动即时写入内存，退出时统一写盘到 `%LOCALAPPDATA%\OSTGUI\config.json`。

## 基本设置

| 项 | 说明 |
|---|---|
| Lua 路径 | 内核读取 lua 的目录，默认 `<Steam>\config\lua`。填错时入库会写到一个内核不看的位置，界面上仍显示成功 |
| 接收更新推送 | 启动后 5 秒检查一次更新，同一版本只提示一次 |
| 版本状态更改通知 | 库页切换版本模式后的提示 |
| D 加密模式 | 普通模式：只在授权窗口内伪装成授权账号，其余时间游戏看到的是当前登录的 Steam 账号。兼容模式：整个会话都把 SteamID 伪装成授权账号。写入内核 `opensteamtool.toml` 的 `[denuvo] mode`，改完需重启 Steam 才生效 |

Steam 路径不提供手动输入，只走自动检测。

## 外观

| 项 | 说明 |
|---|---|
| 主题 | 浅色 / 深色 / 跟随系统 |
| 显示效果 | 无 / 云母 / 亚克力 |
| 侧边栏宽度 | 150–600，逻辑像素 |

云母与亚克力需要 Windows 11（亚克力需 22H2 及以上）。系统不支持时按纯色底显示。

## 清单源

入库时下载清单用的源，按优先级依次尝试。

| 源 | 需要的密钥 | 说明 |
|---|---|---|
| MHub | API Key | 按 depot+gid 取，24 小时过期，过期后回 403 |
| Hubcap | API Key | 按 depot+gid 单份生成；免费额度为单份 1500 次/日 |
| Sudama | 不需要 | 只提供 depot 密钥与访问令牌；有「刷新缓存」与「导入文件…」 |

每行右侧的「测活」用一组固定的 depot+gid 单独请求该源，结果显示在「连通性」里。Sudama 是密钥源，不显示测活。

「清单按需投喂」：开启后监控 Steam 的 `content_log.txt`，发现取不到清单就立刻补一份写进 depotcache。仅在 OSTGUI 运行期间生效。

## 请求码源

内核在运行时向 Steam 取清单请求码（`GetManifestRequestCode`）时用的源，与上面的清单源是两套东西。

- 勾选即参与，顺序就是级联顺序；全不勾会在 `manifest.lua` 里写短路配置，等于关闭请求码。
- 改动实时生效，不需要重启 Steam。
- 勾选变化会**覆盖** `<Steam>\config\lua\manifest.lua`，不留备份。已有自定义内容时先自行备份。

## 运行时日志

- 「复制全部」「清空」只影响界面里这份会话日志。
- 「打开日志文件夹」打开 `%LOCALAPPDATA%\OSTGUI\logs`。
- 「日志文件保留行数」是硬上限，超出后把文件重写为最后若干行，不留 `.1` / `.2` 备份。

日志里的每一行都带时间和进程号。GUI、监控子进程、成就子进程共用同一份 `ostgui.log`；联机宿主另写 `onlinehost.log`。

各文件与目录的含义见 [09-文件位置](09-文件位置.md)。
