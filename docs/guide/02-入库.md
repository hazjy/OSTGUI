# 02 · 入库

> 适用版本：v1.8.4

入库 = 为某个 AppID 生成 `<Steam>\config\lua\<AppID>.lua`，并按设置把清单与密钥准备好。

## 前置

设置页「清单源」至少有一项可用（[01-安装](01-安装.md) 第三节）。只填 Sudama 也能入库，但不会下载清单文件。

## 步骤

1. 打开「搜索入库」，在输入框填入游戏名称、AppID 或 Steam 商店链接。
2. 点「搜索」。
3. 在结果卡片上选择要入库的条目：卡片右下角的入库按钮（箭头落进托盘的图标）开始入库；旁边的信息按钮查看详情。
4. 入库过程中按钮会变成「取消」，可以随时中止。取消后已写入的清单留在 depotcache，Lua 不会写。

成功判据：日志出现 `已生成 Lua 文件：<Steam>\config\lua\<AppID>.lua`，库页出现该游戏。

## 三个勾选项

| 选项 | 打开时 | 关闭时 |
|---|---|---|
| 添加所有DLC | 一并写入 DLC 的 `addappid` | 只处理主游戏 |
| 写入固定版本配置 | 在 Lua 里预写注释形式 `--setManifestid(...)`，锁住当前版本 | 游戏更新后自动跟随新版本 |
| 下载 Manifest | 把清单文件下到 depotcache，启动更快 | 只生成 Lua，清单由内核在运行时按请求码取 |

固定版本的取舍：锁定后游戏不随 Steam 更新，需要新内容时到库页切回自动更新。写进去的是注释形式，实际锁版本由内核完成，见 [03-库与启动](03-库与启动.md)。

## 结果里的两类提示

入库结束后可能看到「缺失清单」或「缺失密钥」，两者含义不同：

- **缺失清单**：这些 depot 的清单没有下载到。内核运行时会按请求码补，通常不影响启动；要预下载可换用别的清单源后重试。
- **缺失密钥**：这些 depot 没有解密密钥。清单拿到也解不开，游戏会在下载阶段失败。常见于新发售或较少人入库的游戏，需要等密钥库收录，或改用手上的 `.ost` 授权（[04-免Steam部署](04-免Steam部署.md) 不涉及，见 Denuvo 页）。
