# 04 · 免Steam部署

> 适用版本：v1.8.4
>
> 位置：左侧「模拟器」页。功能是把游戏目录改造成不依赖 Steam 客户端也能启动的形态。

## 界面操作

1. 选「免Steam」分段。
2. 「游戏 EXE:」点「浏览...」选游戏主程序。
3. 填「AppID:」。
4. 需要时展开「部署选项」与「更多配置」，见下。
5. 点「开始部署」，看「部署日志」。

成功判据：部署日志里每一步都完成；未勾「跳过 GBE 部署」时游戏目录出现 `steam_settings`；双击游戏 exe 能启动。

## 部署选项

| 选项 | 默认 | 说明 |
|---|---|---|
| 备份原 EXE | 开 | 保留 `.bak`，还原时用 |
| 跳过 Steamless 脱壳 | 关 | 已经脱过壳、或游戏本身没有 SteamStub 时勾 |
| 跳过 GBE 部署 | 关 | 只脱壳、不铺模拟器，适合本身不依赖 Steam 初始化的游戏 |
| 仅试运行（不修改文件） | 关 | 只走流程并打印将要做的事 |

「高级设置」里的 Steamless 超时默认 5 分钟，包体大的游戏可以加。

## 更多配置

打开后是写进 `steam_settings` 的模拟器参数：

| 分组 | 项 |
|---|---|
| 账号与身份 | 选择账户后自动填充用户名与 SteamID |
| 语言 | 模拟器回报给游戏的语言 |
| DLC 管理 | 全解锁所有 DLC / 仅解锁白名单（每行 `AppID=名称`） |
| 网络模式 | 离线模式、完全禁用网络、部署 SteamAPICheckBypass |

这几项只在模拟器层面生效，与内核的入库配置是两套东西。

## 还原

「一键还原」撤掉部署时写进游戏目录的产物（EXE/DLL 备份、`steam_settings`、Bypass），回到部署前状态。

`.bak` 已存在时不会覆盖，需要重新备份就先自行删掉旧的。

## 边界

- 自带反作弊、或依赖 `winmm` 之类系统组件的游戏，可能不适配 Bypass（默认不勾）。
- 与联机互斥：部署后游戏不再连接真 Steam，[05-联机](05-联机.md) 的三条路线全部失效。要联机先「一键还原」。

## 免育碧（实验性）

同一页面切到「免育碧（实验性）」：选游戏安装目录（含 `uplay_r2_loader64.dll` 的目录）→ 部署 → 「还原」可回退。

只覆盖传统单 loader 的育碧 R2 游戏；多组件 UC 栈（如 UNO 的 `ubiservices`/`uprofile`/`dbdata`）不在支持范围。该功能处于挂起状态。
