# OSTGUI v1.3.0 更新说明

> 适用版本：1.3.0（对比上一版本 1.2.2）
> 本版本的核心主题：**全新「免 Steam 启动」功能正式可用**，以及一批影响日常使用的稳定性修复。

---

## 一、全新功能：免 Steam 启动（S.A.C 页面）

本版本最大的新增。选择任意 Steam 游戏的主程序 EXE 并填入 AppID，一键完成"脱壳 + 模拟器部署"，之后无需启动 Steam 即可直接运行游戏。

### 工作流程

1. **SteamStub 脱壳**：自动调用 Steamless 移除游戏 EXE 上的 SteamStub 加密壳（未加壳的游戏会自动跳过此步，不会报错中断）；
2. **Goldberg 模拟器部署**：将 GSE（gbe_fork）模拟器 DLL 替换进游戏的 `steam_api.dll / steam_api64.dll` 位置（原文件备份为 `.dll.bak`），并生成完整的 `steam_settings` 配置；
3. **可选增强**：
   - **SteamAPICheckBypass**：部署 winmm.dll 劫持与文件重定向规则，向游戏的自身完整性检查隐藏模拟器痕迹（默认关闭，个别自带 winmm 依赖或反作弊的游戏慎用）。

### 配置项一览

| 分类 | 配置 |
|---|---|
| 基础 | 游戏 EXE 选择（支持从同目录 `steam_appid.txt` / `appmanifest_*.acf` 自动填充 AppID）|
| 部署选项 | 备份原 EXE、跳过脱壳、跳过模拟器、仅干跑预览、Steamless 超时（分钟）|
| 身份 | 从本机 `loginusers.vdf` 选择 Steam 账户，自动填充账号名与 SteamID64 |
| 语言 | schinese / english / japanese 等 13 种，写入模拟器配置 |
| DLC | 全解锁模式，或按 `AppID=名称` 白名单精确控制 |
| 网络 | 离线模式、完全禁用网络 |
| 反检测 | SteamAPICheckBypass 开关 |

以上所有选项均持久化到配置文件，重启后保持。

### 实测情况

- **有壳游戏**（Ib，SteamStub v3）：完整走通"脱壳 → 替换 EXE → 部署模拟器"全链路 ✅
- **无壳老游戏**（半条命）：自动识别为无需脱壳，直接部署 ✅
- 两类游戏均可脱离 Steam 客户端直接启动。

### 与旧版的兼容性说明

- 部署会修改游戏目录文件；如需还原，将 `*.exe.bak`、`steam_api*.dll.bak` 改回原名并删除 `steam_settings` 文件夹即可；
- 2016 年前的老 Steam SDK 游戏（如半条命）会额外生成 `steam_settings/steam_interfaces.txt`，属正常现象。

## 二、稳定性修复

### 1. 日志系统线程安全（重要）

修复了一个长期存在的深层缺陷：后台线程直接写入界面绑定的日志集合，导致集合变更事件在非 UI 线程触发绑定更新，产生各种"莫名其妙"的崩溃或失败提示，并且会**掩盖真实错误信息**。

- `LogService.AddLog` 现在自动封送回 UI 线程，任何线程调用均安全；
- 设置页的日志订阅处理器全面防御化，不再向外抛出异常。

> 此前"Sudama 刷新总是奇怪失败""错误提示看不懂"一类问题，根源都在这里。

### 2. 配置文件乱码自愈

部分用户配置文件中的清单源名称为历史遗留的乱码编码。现在应用加载配置时会以代码内置的正确名称自动刷新预置源显示字段（API Key、启用状态等用户数据不受影响），下次保存即彻底痊愈。

### 3. 其他

- 移除启动时误报的 `ERROR: Services is null` 日志（实际并非错误）；
- 清理重复的依赖注入注册代码。

## 三、Sudama 密钥缓存改进

- **并行下载**：depot key 与访问令牌同时拉取，总耗时取较慢者而非两者之和；
- **流式接收**：不再把十几 MB 的响应体复制成大字符串处理；
- **超时合理化**：单次尝试超时由固定 300 秒调整为随设置联动（最低 120 秒），卡死的连接更快暴露；
- **重试间隔 1.5 秒**：给服务端限流留出喘息；
- **量化日志**：成功后显示条数、体积、耗时，例如 `Sudama 密钥下载完成：220440 条，16,485 KB，耗时 7.3s`；
- **新增手动导入**：设置页 Sudama 行新增"导入文件…"按钮。服务器线路不佳时，可直接用浏览器下载 `depotkeys.json` / `appaccesstokens.json` 后导入（自动按文件名或内容识别类型），效果与在线刷新一致。

## 四、界面清理

- 免 Steam 页移除了三个从不生效的输入项（启动验证超时 / 启动参数 / 工作目录）及其配置字段，避免误导；
- 修复"开始部署"按钮上一处失效的绑定（按钮的实际启用逻辑不受影响）;
- 修正 DLC 白名单的提示文案（实际写入位置为 `steam_settings/configs.app.ini`）。

---

## 五、工程与仓库

- **构建脚本整合**：全部构建入口收敛为根目录 `build.bat`——安静输出、完整日志落盘 `%TEMP%\ostgui_build.log`、失败自动打印错误摘要、支持 `build.bat /r` 构建后直接启动；删除了 5 个过时/失效的脚本；
- **NoSteamLauncher 折叠入主仓库**：此前它是一个嵌套的独立 git 仓库（克隆主仓库时源码会丢失），现作为普通源码目录纳入统一版本控制，其运行时二进制资源（脱壳插件、GSE 模板等约 22MB）一并纳入；
- **第三方组件声明**：新增 `docs/THIRD-PARTY-NOTICES.md`，列明随仓库分发的 GSE（LGPL-3.0）、Steamless（CC BY-NC-ND 4.0）、SteamAPICheckBypass（MIT）组件的来源与许可证。

---

## 六、已知事项

1. Sudama 的 `depotkeys.json`（约 16MB）下载速度取决于服务器与你的网络线路；若应用内下载缓慢，请使用浏览器直连下载后通过"导入文件…"导入；
2. 带自定义 winmm.dll 依赖或反作弊系统的游戏，开启 SteamAPICheckBypass 可能冲突（该选项默认关闭）；
3. 部署后的游戏存档路径由模拟器接管，与 Steam 云存档不互通。

---

## 升级方式

下载新版后解压覆盖旧版程序文件即可。配置、缓存位于 `%LOCALAPPDATA%\OSTGUI`，升级不影响。
